# Полный гайд: «Банковское приложение» на Arch Linux + Fish

**Автор курсовой:** Александр Шеховцов · **Группа:** ПКС 5-24  
**Приложение:** C++20, REST API на cpp-httplib, SQLite3, nlohmann/json, CMake, vcpkg.  
**Система:** Arch Linux x86_64. **Терминал:** Fish. **Интерфейс:** текстовое консольное меню.

> Команды с пометкой `fish` вводятся непосредственно в терминале Fish. Не используйте PowerShell или `cmd.exe`. Никаких программ на Python, JavaScript или Qt для сборки не требуется.

## 1. Что находится в архиве

| Файл или папка | Назначение |
| --- | --- |
| `src/models/`, `include/models/` | `Person`, `Client`, `BankAccount`, `Transaction` |
| `src/services/` | `BankService`: правила, переводы, проверки |
| `src/storage/` | `Database`: чтение/запись SQLite, SQL-транзакции |
| `src/api/` | `BankApi`: JSON REST API |
| `src/server/main.cpp` | Входная точка HTTP-сервера |
| `src/cli/` | `BankCli`, консольные меню и HTTP-клиент |
| `vcpkg.json` | Перечень и зафиксированный baseline зависимостей |
| `CMakeLists.txt` | Два исполняемых файла и серверная библиотека |
| `CMakePresets.json` | Arch Release/Debug с Ninja и vcpkg |
| `run_server.fish` | Запуск сервера из корня проекта |
| `run_cli.fish` | Запуск консольного клиента |
| `data/` | Здесь появится `bank.db` |
| `README.md` | ООП, UML, схема SQLite, API и сценарий защиты |

Система состоит из **двух отдельных процессов**. Консоль **не читает базу SQLite**; она посылает HTTP-запросы на `127.0.0.1:8000`. Сервер проверяет правила операций и сохраняет данные в файле.

## 2. Установка всего необходимого

Откройте терминал Arch Linux и введите:

```fish
sudo pacman -Syu --needed base-devel gcc cmake ninja git curl zip unzip tar fish
```

Если вы ещё не в Fish, выполните `fish`. Проверьте инструменты:

```fish
fish --version
uname -m
g++ --version
cmake --version
ninja --version
git --version
```

`uname -m` должен показать `x86_64`. Если компьютер `aarch64`, потребуется другой triplet, и данный готовый пресет не подходит.

Не нужно устанавливать библиотеки `cpp-httplib`, `nlohmann-json`, `sqlite3` в проект вручную: для этого используется **vcpkg**. Утилита `sqlite3` из pacman может пригодиться только для просмотра базы и необязательна для запуска.

## 3. Установка vcpkg

Один раз выполните:

```fish
git clone https://github.com/microsoft/vcpkg.git "$HOME/vcpkg"
cd "$HOME/vcpkg"
./bootstrap-vcpkg.sh
set -Ux VCPKG_ROOT "$HOME/vcpkg"
```

Проверка:

```fish
echo $VCPKG_ROOT
"$VCPKG_ROOT/vcpkg" version
ls "$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake"
```

В `vcpkg.json` указан реальный `builtin-baseline`; его **не удаляйте**. Он задаёт исходный набор портов для воспроизводимой установки. Если vcpkg был установлен ранее, только задайте нужный путь через `set -Ux VCPKG_ROOT /полный/путь/до/vcpkg`.

## 4. Распаковка архива

Допустим, ZIP находится в папке `Загрузки`, которая в некоторых системах имеет имя `Downloads`. Пример для `~/Downloads`:

```fish
cd ~/Downloads
unzip banking-app-arch-fish.zip
cd banking-app-arch-fish
```

Если путь иной, откройте нужную папку и перейдите в каталог `banking-app-arch-fish`. Проверьте, что вы в правильной директории:

```fish
pwd
ls CMakeLists.txt CMakePresets.json vcpkg.json README.md
```

## 5. Установка трёх библиотек

**Находясь в корне проекта**, выполните:

```fish
"$VCPKG_ROOT/vcpkg" install --triplet x64-linux
```

Зависимости загружаются из Интернета; при первом запуске их может потребоваться скомпилировать. Все зависимости описаны в `vcpkg.json`; дополнительных менеджеров вроде pip/uv нет.

## 6. Сборка Release

Простейший способ:

```fish
cmake --preset arch-release
cmake --build --preset arch-release
```

После успешной сборки:

```fish
ls -lh build/bank_server build/bank_cli
```

Оба исполняемых файла **Linux ELF**, без расширения `.exe`. Чтобы убедиться:

```fish
file build/bank_server build/bank_cli
```

Если необходимо пересоздать конфигурацию:

```fish
rm -rf build
cmake --preset arch-release
cmake --build --preset arch-release
```

Сборка без пресета (эквивалент):

```fish
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE="$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake" -DVCPKG_TARGET_TRIPLET=x64-linux
cmake --build build
```

Для отладки исходного кода: `cmake --preset arch-debug; and cmake --build --preset arch-debug`. Отладочная версия появится в `build-debug/`.

## 7. Запуск сервера

Откройте **терминал № 1** в корне проекта:

```fish
fish ./run_server.fish
```

Пример вывода:

```text
Банковский сервер: http://127.0.0.1:8000
База данных: data/bank.db
Для остановки нажмите Ctrl+C.
```

Сервер занимает этот терминал, это ожидаемое поведение. Он автоматически создаст `data/bank.db` и таблицы `clients`, `accounts`, `transactions`.

Проверка подключения из **другого** терминала:

```fish
curl http://127.0.0.1:8000/health
```

Ожидается JSON со значениями `"status":"ok"` и `"message":"Сервер работает"`.

## 8. Запуск консольного клиента

Откройте **терминал № 2**, перейдите в корень проекта:

```fish
fish ./run_cli.fish
```

Меню появится сразу. Если сервер ещё не запущен, клиент сообщит об отсутствии подключения, но не завершится аварийно.

Вместо скриптов можно использовать `./build/bank_server` и `./build/bank_cli`, но тогда **сначала** перейдите в корень проекта. В ином рабочем каталоге SQLite может создать новую базу `data/bank.db` в неожиданном месте.

При необходимости другой URL сервера задают в Fish:

```fish
set -gx API_URL http://127.0.0.1:8000
fish ./run_cli.fish
```

Сброс: `set -e API_URL`. Сервер по умолчанию всегда привязан к `127.0.0.1:8000`.

## 9. Главное меню

```text
=====================================
         БАНКОВСКОЕ ПРИЛОЖЕНИЕ
=====================================
1. Добавить клиента
2. Показать всех клиентов
3. Найти клиента
4. Изменить данные клиента
5. Удалить клиента
6. Управление счетами
7. Банковские операции
8. История операций
0. Выход
=====================================
```

Введите номер и нажмите **Enter**. Неверный ввод не прекращает работу клиента. Из подменю выходите пунктом `0`. В главном меню `0` завершает программу.

### 9.1. Добавление клиента

Нажмите `1`, введите ФИО, возраст от 18 до 100 и телефон. Пример:

```text
ФИО: Иван Иванов
Возраст (18–100): 25
Телефон: +996 555 111111
Клиент добавлен.
```

Запишите показанный `ID`. Он присваивается автоматически, номер заранее не фиксирован.

### 9.2. Просмотр, поиск и редактирование

Пункт `2` — все клиенты. Пункт `3` — поиск по ID или части ФИО. Например, `иван`, `ИВАН` и `ван` находят `Иван Иванов`, без учёта регистра русских букв.

Пункт `4` — ID клиента, затем подменю изменения ФИО, возраста или телефона. Пункт `5` — удаление, требующее подтверждения. Удалить клиента с открытым счётом нельзя.

### 9.3. Открытие и просмотр счетов

Пункт `6` открывает меню банковских счетов:

```text
1. Создать счёт
2. Показать все счета
3. Найти счёт
4. Показать счета клиента
5. Посмотреть баланс
6. Закрыть счёт
0. Назад
```

Создайте счёт, указав **ID существующего клиента**. Счёт всегда открывается с `0.00 KGS`. Полученный ID счёта **не обязан совпадать** с ID клиента.

Закрыть счёт можно только если баланс нулевой и нет ни одной операции (в том числе входящих переводов) в истории. Это правило защищает журнал операций.

### 9.4. Денежные операции

Пункт `7` открывает:

```text
1. Пополнить счёт
2. Снять деньги
3. Перевести деньги
4. Посмотреть историю операций
0. Назад
```

Для пополнения и снятия вводятся номер счёта и сумма. Для перевода — номер отправителя, получателя и сумма. Запрещены суммы `0`, отрицательные значения, превышение баланса и перевод на собственный счёт.

**Формат суммы:** `150.50`, `10`, `10.5` — допустимо. Запятая, текст `сом` и более двух дробных разрядов недопустимы. Денежные расчёты — только целые числа тыйын (`int64_t`).

### 9.5. История

Пункт `8` главного меню открывает историю выбранного счёта. Показываются дата в UTC, вид операции, сумма и номера двух счетов при переводе. Операции сохраняются после перезапуска.

## 10. Практический сценарий с двумя клиентами

Шаги приведены для чистой базы. В других случаях ID могут отличаться.

1. Добавьте клиента **Иван Иванов**, 25 лет, `+996 555 111111` (допустим, ID `1`).
2. Добавьте клиента **Айгүл Осмонова**, 22 года, `+996 555 222222` (допустим, ID `2`).
3. Создайте счет для клиента `1` (допустим, ID счёта `1`).
4. Создайте счет для клиента `2` (допустим, ID счёта `2`).
5. Пополните счёт `1` на `500.00`.
6. Снимите со счёта `1` сумму `50.00`.
7. Переведите со счёта `1` на счёт `2` сумму `100.50`.
8. Проверьте оба баланса: **349.50 KGS** и **100.50 KGS**.
9. Просмотрите историю каждого счёта; перевод отображается у обоих.
10. Попробуйте снять со счёта `2` сумму `999.00`; появится ошибка «Недостаточно средств на счёте».
11. Перезапустите сервер и клиент; затем вновь проверьте счета и историю.

## 11. Ручные запросы REST API (дополнительно)

Это **необязательная диагностика** через `curl`; штатный консольный клиент по-прежнему использует `cpp-httplib`.

```fish
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/clients
curl -G --data-urlencode 'search=ИВАН' http://127.0.0.1:8000/clients
curl -X POST http://127.0.0.1:8000/clients -H 'Content-Type: application/json' -d '{"name":"Алия Садыкова","age":23,"phone":"+996 700 123456"}'
curl -X POST http://127.0.0.1:8000/accounts -H 'Content-Type: application/json' -d '{"client_id":1}'
curl http://127.0.0.1:8000/accounts
curl -X POST http://127.0.0.1:8000/accounts/1/deposit -H 'Content-Type: application/json' -d '{"amount":"200.25"}'
curl -X POST http://127.0.0.1:8000/accounts/1/withdraw -H 'Content-Type: application/json' -d '{"amount":"10.00"}'
curl -X POST http://127.0.0.1:8000/transfers -H 'Content-Type: application/json' -d '{"from_account_id":1,"to_account_id":2,"amount":"30.00"}'
curl http://127.0.0.1:8000/accounts/1/transactions
```

Важно: в примерах `1` и `2` — **условные** ID, подставляйте реальные ID из результатов API.

При недостатке средств ответ имеет код `409` и JSON:

```json
{"error":{"code":"insufficient_funds","message":"Недостаточно средств на счёте"}}
```

## 12. Просмотр SQLite

Установите **необязательную** утилиту для просмотра хранилища:

```fish
sudo pacman -S --needed sqlite
```

Из корня проекта:

```fish
sqlite3 data/bank.db '.tables'
sqlite3 data/bank.db 'SELECT * FROM clients;'
sqlite3 data/bank.db 'SELECT * FROM accounts;'
sqlite3 data/bank.db 'SELECT id, account_id, target_account_id, type, amount_cents, created_at FROM transactions;'
```

Колонка `balance_cents` хранит **тыйн**, а не сом: `100.50 KGS` = `10050`. Чтобы сохранить содержимое, не удаляйте `data/bank.db`. Для резервного копирования остановите сервер и скопируйте файл в другое место.

## 13. Частые ошибки

| Симптом | Решение |
| --- | --- |
| `fish: command not found` | `sudo pacman -S fish`; затем запустите `fish` |
| `g++`, `cmake` или `ninja` отсутствует | Установите через `sudo pacman -S --needed base-devel gcc cmake ninja` |
| `$VCPKG_ROOT` не задан | `set -Ux VCPKG_ROOT "$HOME/vcpkg"` |
| Ошибка `CMAKE_TOOLCHAIN_FILE` | Убедитесь, что есть `"$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake"` |
| `find_package` не находит библиотеки | `"$VCPKG_ROOT/vcpkg" install --triplet x64-linux`; очистите `build`, затем повторите пресет |
| Fish-скрипт не запускается | Выполните `fish ./run_server.fish` или выдайте `chmod +x run_server.fish run_cli.fish` |
| Сервер не стартует | Проверьте, занят ли порт: `ss -ltnp | grep ':8000'` |
| CLI не видит сервер | Сначала запустите сервер, затем проверьте `curl http://127.0.0.1:8000/health` |
| Русский текст отображается квадратами | Проверьте `locale`, установите шрифт терминала с кириллицей |
| Данные пропали | Проверьте папку запуска: запускайте `fish ./run_server.fish` из корня проекта |
| Невозможно удалить клиента/счёт | Проверьте связанные счета, ненулевой баланс и историю операций |

## 14. Что показать преподавателю

1. Два независимых терминала: сервер и CLI.
2. Добавление клиента и подтверждение данных в SQLite.
3. Наследование `Client : public Person` и виртуальный `getInfo()` через `Person&`.
4. Инкапсуляцию баланса в `BankAccount`.
5. Открытие счетов, пополнение, снятие, перевод.
6. Отказ в снятии сверх остатка; запрет перевода на собственный счёт.
7. `BankService::transfer()` + `Database::TransactionScope` — все изменения атомарны и откатываются при ошибке.
8. Историю двух счетов и её сохранение после перезапуска сервера.
9. Разделение файлов модели, API, базы и HTTP-клиента.

Курсова́я использует **фиктивные деньги** и демонстрирует программирование, а не реальные финансовые операции. UML, таблица методов всех классов, перечень API и объяснение основных принципов ООП находятся в `README.md`.
